### A.1 참여자 기록 데이터 구조 (제37조의4 정박, 오너 제안 채택)
```
참여자 이름 또는 사번          ← 식별정보(제37조의4 법정)
소속 / 역할
근로자 / 근로자대표 구분        ← 제37조의4가 "근로자대표" 명시
참여 방법(순회점검·면담·설문·기타)  ← 제37조의2
참여 시각
확인 방식(관리자 출석기록 / 본인 확인 / 서명)
서명 이미지 또는 확인 기록(선택 — 회사 정책으로 필수화 가능)
```
- **이름/식별정보 = 지원**(제37조의4 기록사항). **서명 = 조문상 명시 의무 아님** → 참여·전달 증빙용 선택 필드, 사업장 정책으로 필수화 옵션. **책임포기/위험수락 프레이밍 금지.**
- ⚠️ 이름·서명을 CloudKit 저장 시 **개인정보처리방침·App Privacy "Data Not Collected" 재검토 필수**(LEGAL-0 게이트와 직결).

### A.2 "상시평가"는 enum 값이 아니라 별도 축 (오너 교정)
- 최초·정기·수시 = **평가 종류(kind)**. 상시평가 = 월간평가+주간공유+매작업일 TBM으로 정기·수시를 **갈음하는 운영 방식(operating mode)**.
- → `RiskAssessmentKind.continuous`를 바로 추가하지 말 것. **`평가 종류` × `운영 방식`을 별도 축**으로 모델링(LEGAL-2 설계 결정).
